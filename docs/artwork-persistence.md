# 耳机外观资源的持久化与重新下载

本文说明 0.8.3 之后的源码改动（尚未发布新版本号）：主界面左侧的图片、三维模型和 Lottie 在第一次取得后持续可用，X4 的在线 Lottie 可以作为产品展示播放，应用设置新增“重新下载在线资源”。另外新增 GitHub Actions，构建 Windows x64 与 ARM64 包。

## 原来的问题

- **没有持久的型号映射。** 型号与颜色只存在于 Host 和界面的内存里。界面又以每次 Host 启动都会变化的会话标识为键，所以断连、重启或重新打开窗口后都要等到完整连接才会再次显示美术。
- **颜色来源不稳定。** 颜色只来自 BLE 广播，30 秒后过期，SPP 会话从不读取。没有颜色就不能请求在线包，也无法选择带颜色的预装图。欢律来源的预装产品图只覆盖 X4，因此其他型号即使连接正确，也常常只显示通用图。
- **频繁全量重置。** 任一设备下载新包导致的资源版本号变化、快照清空造成的版本号回落，以及颜色变化，都会清空所有设备的美术并重新加载（三维模型重新解析，Lottie 从头播放）。请求失败后不再重试，只能靠“刷新状态”碰巧触发重置。
- **网络在关键路径上。** Host 即使有有效缓存，也要先完成在线检查。网络超时被当作取消，连预装图也不返回。界面放弃等待后，Host 仍保留租约，导致泄漏。
- **X4 Lottie 选不到、放不对。** control 包解析是全有或全无：Lottie 路径为目录，或图片按 lottie-android 的 images 目录约定存放，整包就会被拒绝。hero 只匹配 detail/model。三个 Lottie 列表被合并后只取第一项。播放时整段时间轴无限循环，也不裁剪画布留白。

## 外观提示（只用于显示）

- **持久化。** Host 把每台已加入白名单设备的产品 ID 和协议颜色保存到 `%LOCALAPPDATA%/HeyMelody/device-appearance.json`。键与 `devices.json` 相同，都是带用途前缀的地址 SHA-256，文件中不出现地址或会话标识。文件损坏只当作缓存丢失，下一次观测会重写。
- **来源优先级。** SPP 核验的产品 ID 可以替换旧值，SPP 读到的颜色优先于广播。经过地址关联校验的 BLE 广播只填补空缺，不会覆盖来自 SPP 的颜色或另一个产品 ID。
- **发布方式。** Host 在设备目录（`UiDevice.ProductId/Color`）中发布这些提示。它们不授予 ControlReady、能力或任何写入权限；快照的 `ProductId` 语义不变，断连时“设备信息”仍显示“—”。

## SPP 颜色读取

两份官方 APK 都把 GET `0x010B` 列为始终可用的基础命令，并从 ACK `0x810B` 的 `payload[1]` 读取无符号颜色字节（见 [颜色审计](research/online-artwork/free4-identity-color-audit.md)）。

- **读取时机。** 型号与能力核验之后，同一客户端对每个产品只读一次，超时 2 秒。
- **失败处理。** 设备拒绝或不应答时只记为颜色未知：不写入用户警告，不中断会话，迟到的应答也不会与后续请求混淆。传输错误仍按原逻辑中断会话。
- **用途。** 读到的颜色会进入快照，并用于选择与颜色相关的 EQ 预设；同一产品已验证的广播颜色只在会话颜色缺失时补充。
- **对实机验证的影响。** 每次建立连接会多 1 次 GET，此前 X4 实机记录的 15 次 GET 将变为 16 次。该命令尚无真机抓包，需要用户在 X4 上复验。

## Host 资源解析

- **缓存优先。** 有在线缓存或预装模型时立即返回，同时在后台检查更新；后台检查按槽位去重，并沿用 10 分钟节流。只有某槽位第一次使用时，才最多等待下载约 10 秒，之后回退到预装图。下载晚完成时通过资源版本号通知界面换图。
- **超时。** 网络超时与其他失败同样处理：30 秒后重试，记录状态，并继续返回缓存或预装图。
- **重新发布。** 同一摘要的包仍被界面租用时，新解包发布到 `<sha256>-<8 位十六进制>` 目录；`current.json` 记录目录名，并兼容旧格式。重新发布会撤销之前的退役标记。Host 启动时清理中断的下载目录和已被替代的包目录。
- **解包版本标记。** 新解包写入 `package.json`（schemaVersion 2）。旧版解包的包在下一次在线检查时重新下载，在此之前继续使用。
- **容错解包。** 单个配置项缺失或格式不支持时跳过该项。压缩包成员或配置路径越界仍拒绝整包；动画中引用包外图片的条目只跳过该条目。
  - 三个 Lottie 列表分别对应 `lottie`、`lottie-left`、`lottie-right`，并保存列表序号和条目的标量字段。
  - Lottie 路径可以是文件，也可以是目录；目录时优先取 `data.json`，否则按签名查找唯一的 Lottie JSON。
  - 图片依次查找 `u+p`、`images/p`、条目声明的图片目录、`p`。用到回退位置时另写一份只改写 `u` 的 `*.heymelody.json`，并记录原件路径与摘要，原件字节不变。
- **hero 选择。** control 包内依次为：模型 > `lottieResList` 中序号最小的 Lottie > detail 图；detail 图同时作为 Lottie 的静态回退。左右耳列表不会成为 hero。规则集中在 `ResourceCoordinator.SelectPackageEntry`，待真实 X4 包和真机反馈确认后再调整。
- **其他。** 目录中不存在的产品 ID（例如另一来源才有的型号）返回“无美术”，不再报错。界面放弃等待时，迟到的租约回执会被立即释放。

## 界面美术目录

- **外观只增不减。** `DeviceVisualCatalog` 合并设备目录提示和所选设备的实时型号/颜色。空值不会清除已知值，只有不同的非空产品 ID 才会替换，并立即撤下上一个产品的美术。
- **共享槽位。** 槽位按（角色、产品 ID、颜色）建立，多台设备共用。每台设备显示的槽位要等新槽位就绪才切换，学到颜色时不会闪回通用图。
- **更新与重置。** `ArtworkEpoch` 由后台实例和单调递增的资源版本号组成：快照被清空时版本号回落不会触发任何操作，版本号前进时在后台重新解析。结果内容相同（类型、摘要、静态回退摘要都一致）时保留原渲染控件，不会重新解析模型或从头播放动画。资源来源或后台服务变化时才整体重置，来源不一致的响应仍不得显示。
- **失败重试。** Host 返回“无美术”视为确定结果。异常或超时按 5 秒、15 秒、1 分钟、5 分钟退避重试；被取消的请求不标记为已完成。
- **渲染保护。** 三维模型控件在包已被替换时显示回退图，不抛异常。

## 产品 Lottie 播放规则

`LottieView` 新增 `LottiePresentation`：默认 `Loop` 保持原行为（Calibration.UI 的引导动画），主界面产品展示使用 `Product`。

- **有分段标记（`dr > 0`）。** 两段及以上时首段播放一次，之后循环末段；只有一段时先播放该段之前的部分，再循环该段。
- **只有零长度分割点。** 分割点之前播放一次，之后循环。
- **没有标记。** 首尾帧在小尺寸 CPU 渲染下比较一致时循环全段，否则播放一次后停在最后一帧，并停止请求后续帧。
- **画布裁剪。** 后台对实际播放区间抽样渲染，取可见像素边界的并集加 4% 留白；测量和绘制都只针对裁剪后的区域。
- **海报。** 加载超过 250 毫秒时先显示该包的 detail 静态图，加载完成后切换为动画；加载失败时显示回退图。

## 重新下载在线资源

应用设置改为 FluentAvalonia 设置卡片，分为外观、耳机资源、设备、关于四组。点击“保存”才提交草稿、每个来源的密钥相互独立、“管理设备”先关闭对话框等原有语义不变。

- **卡片行为。** “重新下载在线资源”作用于已保存的来源。在线资源关闭、当前服务不支持或正在执行时按钮禁用，卡片说明会给出原因。执行期间显示进度环，结束后以内联 `FAInfoBar` 显示成功或部分失败，结果同时写入操作记录；关闭对话框不会中断后台操作。
- **IPC。** 新增 `redownloadResources` 操作，返回 `UiResourceRedownloadResult`。这是增量操作与字段，公共 IPC 仍为 schema 3；旧 Host 会以普通失败回应。
- **Host 处理。** 同一时间只执行一次，客户端断开后继续完成。它强制重新下载当前来源的配置，以及所有已知美术槽位：本次会话的目标、磁盘上已有的槽位和设备外观提示对应的槽位。新文件校验通过后才发布，失败时保留原文件；配置只有内容版本更高时才采用，配置变化后按原规则重启控制会话。

## 持续集成

`.github/workflows/windows-build.yml` 在 push（`main`、`arch/**`）、pull request 和手动触发时运行。

- **`test`：** 在 windows-latest 上执行 `Build-Client.ps1 -TestsOnly`，运行 13 个默认离线/模拟 runner（包含 Host 与 Windows.OfflineChecks），并上传界面截图与报告。
- **`package`：** 依赖 `test`，按 x64、ARM64 两个矩阵执行 `Build-Client.ps1 -Architectures <arch> -SkipTests`，上传 `release/HeyMelody_Windows_<version>/` 为构建制品。版本号可在手动触发时指定，否则沿用脚本默认值。

ARM64 包在 x64 runner 上交叉发布，CI 不运行它。`-TestsOnly` 不能与 `-SkipTests`、`-FinalizeOnly` 或 `-ValidationPath` 同时使用。
