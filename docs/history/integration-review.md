# 阶段 5 集成审阅

2026-10-06 02:58 UTC 对 WPF 0.5.0 进行了有界静态审阅。在当时已读范围内未发现阻塞问题；该结论不覆盖后来的 Avalonia 或共享托盘后台，也不等同完整客户端、发布包或真实设备验证。当前说明见[后台架构](../backend-architecture.md)和[日常控制层](../daily-notes.md)。

审阅覆盖客户端 Bridge、主窗口、UI contracts、原生服务、Host 入口、RPC 格式及构建脚本七个文件，共 939 行，并枚举指定发布文件的名称、大小和时间。没有执行构建、测试、GUI、后台程序或设备命令，也没有核验发布程序集架构、完整 manifest、ZIP 或签名。

核对的集成行为为：

- GUI 正式启动每架构的独立 Host，GUI 与 Console 运行时分开，避免覆盖同名依赖。
- 每次 IPC 请求提交一次并关联 schema/id；失联、超时或格式错误保留未知结果，不自动重发设置。
- 原生服务发现位于工作进程中，父进程施加请求时限，UI 不直接等待同步 SDP。
- 写入绑定精确设备身份、UI 选择和会话快照，不按设备名称转移旧操作。
- ACK、是否提交和状态回读分别保留；无需提交但目标已匹配的操作可正常结束，部分或未知提交不显示为完整成功。
- 读取失效关闭写入，未保存 EQ 编辑不被常规刷新覆盖；可能丢弃编辑及 Hi-Res/空间互斥操作有确认路径。

当时仅确认发布目录布局与代码一致，没有执行二进制或证明 ARM64 实机行为。对 Daily 的协议及新鲜状态门控沿用其独立记录，不把此次集成审阅扩大为重新核验全部协议。

随后 0.6.x 改为分区刷新，保留未查询分区的最新缓存及本地编辑，后台读取不再全局禁用控件；客户端在核验同设备、完整结果和安全重复条件后最多进行一次后续尝试。ACK 原始事实仍与回读独立。0.7.0 的共享托盘后台进一步采用推送架构，具体行为及后来验证以当前文档为准。
