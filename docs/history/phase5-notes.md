# 阶段 5：WPF 0.5.0 交付

2026-10-06 完成 WPF 0.5.0，目标为精确匹配 `06EC10` 的 OPPO Enco X4。本页整理当时实现和验证，不适用于后来的 Avalonia、共享托盘后台或当前发布包。当前行为见[文档索引](../README.md)、[后台架构](../backend-architecture.md)和[日常控制层](../daily-notes.md)。

| 功能 | 历史实现 |
| --- | --- |
| 电量 | `0106`，保留组件及原值，解析充电位，无法解释时保持未知 |
| ANC | `010C/0404`，按型号配置的父子编号构建位图 |
| 内置 EQ | `010F/0406`，原始 ID 0、7、2、1、3 |
| 自定义 EQ | `0122` 空载荷查询；`0418` 完整条目创建、修改或选用 |
| 双连 / 游戏 | feature `11` / 已回报的 `06` 或 `28` |
| 空间 / Hi-Res | `012A/0422` 优先，保留旧 `1B`；Hi-Res 为 `18`，互斥前置操作须确认 |

十段 EQ 频点为 31、62、125、250、500、1000、2000、4000、8000、16000 Hz。内置预设与自定义 ID 分开：已有自定义项通过 `0418 action2` 及刚回读的完整条目选用，不调用 `0406[customId]`。创建采用 action1、默认范围 -6..+6 dB；更新保留条目原范围与合法 UTF8 名称。是否已保存并选用以内容和 selected 回读确认，不推断固件一定自动选中。

当时 WPF 通过私有标准输入/输出与独立 Host 通信，每架构分别发布 GUI 和后台运行时，日常状态每八秒读取。写入必须绑定设备选择、会话和新鲜快照，命令/序号匹配，同一连接不复用序号。0.5.0 的 SET 不自动重放，GET 可有限重连；未保存 EQ 编辑受到保护。后来 0.6.x 的分区刷新及客户端有界重试、0.7.0 的推送架构均有独立说明，不继承这次验证结果。

| --- | --- | --- |
| x64 | 通过 | 通过 |

最终发布版只读验证时间为 2026-10-06 02:55 UTC：每个已执行架构两轮共 20 个 GET，0 个 SET、0 个其他命令。查询覆盖电量、ANC、EQ、多设备、游戏、空间和 Hi-Res；缺失的盒组件保持未知。六类真实设备 SET 未在此阶段执行；离线设置测试、只读查询或状态预览不能替代这些验证。ARM64 只有交叉构建和静态检查。
