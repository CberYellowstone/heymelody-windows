# 阶段 5 协议结论

2026-10-06 通过本地官方 APK、X4 配置及参考源码静态核对日常协议，并对当时 Daily 代码作有界审阅。本页整理已核实的协议事实和历史修正，未执行真实设备 SET、完整客户端或 ARM64 运行。当前行为见[日常控制层](../daily-notes.md)，完整取证定位保存在本地档案。

X4 的内置 EQ 使用原始 protocolIndex，与 modeType 分开：

| protocolIndex | modeType | 标签 |
| --- | --- | --- |
| 0 | 42 | 丹拿原声 |
| 7 | 43 | 丹拿高解析 |
| 2 | 28 | 纯享人声 |
| 1 | 46 | 清亮高音 |
| 3 | 29 | 澎湃低音 |

ANC 父子编号独立：父 1 为降噪，子 7/4/5/6 分别为智能/深度/中度/轻度；父 11 为自适应，子 12/13/14 为更少噪音/标准/更多噪音；父 0/2 为关闭/通透，子 3/8 为对应子状态。未知编号不得猜成默认档。

电量 `0106/8106` 的布局为 `[status,count,(component,raw)*count]`，组件 1/2/3 为左右耳/盒。`raw&0x7F` 为数值，`raw&0x80` 为充电位。APK 的 UI 修正规则不是“127 为 wire 未知哨兵”的证明；Windows 对无法解释的值显示未知，0 不证明物理不在位或精确耗尽。

ANC `010C/810C` 的普通响应为 `[status,kind,type,bitmap...]`；type1/5 按 LSB 位图解析，type2 为 level，未知或多位状态保持原值。kind4 仅在已核实子 4/5/6/7 范围内归为智能实时切换。子档 `0404` 使用 `[1,1,bitmap...]`：例如 bit4 为 `01 01 10`，bit8 为 `01 01 00 01`。

2026-10-08 的[ANC 主模式复核](../research/anc-mode-prompt.md)补充主按钮发送顶层父编号，不能用默认子档代替。X4 自适应父 bit11 为 `01 01 00 08`；父态不能证明具体子档，提示音因果仍需实机核对。

内置 EQ 沿 `010F/0406`，自定义 EQ 沿空载荷 `0122` 及完整条目 `0418`，两个 ID 空间不混用：

| 数据 | 布局 |
| --- | --- |
| `8122` | `[status,count,entries...]` |
| 每个 entry | `[selectedU8,minS8,maxS8,idU8,nameLengthU8,UTF8Name,bandCountU8,(frequencyLE16,gainS8)*N]` |
| `0418` | `[action,minS8,maxS8,idU8,nameLengthU8,UTF8Name,bandCountU8,(frequencyLE16,gainS8)*N]` |

名称长度是 UTF8 字节数，单字节上限 255 不代表 UI 接受任意 255 字节名称。selected 在原协议中为完整字节，客户端仅接受 0/1；数量、唯一 ID/频率、UTF8 和增益范围须分别校验。X4 十段为 31、62、125、250、500、1000、2000、4000、8000、16000 Hz。

action1 创建的默认增益范围 -6..+6 dB 有 APK 证据；更新使用刚回读条目的范围。选用已有自定义项及滑块更新均发送 action2 完整条目，不能调用 `0406[customId]`。创建请求没有 selected 字段，是否自动选中须以 `0122` 回读确认；不能补发猜测的激活命令。合法已有名称应原样保留，不能套用新建名称的额外输入限制。

双连使用 feature `11`，游戏模式依据实际状态选择 `06` 或 `28`；功能版本数字不等于当前开关值。三模式空间使用 `012A/0422` 的 0/1/2，旧 feature `1B` 不能表达头部跟踪。Hi-Res feature `18` 与空间互斥时，前置关闭须获得 ACK 并回读；任一不确定便停止后续写入。独立游戏音效 `012B/0423` 不等于游戏模式，X4 的 gameSoundMutexes `[1,3]` 也不包含空间项。

当时审阅核验的修正包括：自定义选用改为 `0418 action2` 完整条目、kind4 限定已知智能子档、`0122` 改为空载荷，以及已有合法 EQ 名称的保留规则。12 项离线资源/配置断言通过；该次核对未运行后端测试或设备 SET，不能宣布整个客户端无缺陷。

0.5.0 单次 SET 与后续客户端有界重试属于不同层次。当前 ACK 接受/拒绝/未知与状态回读仍独立；只读重连不能改写原 SET 的失败或接受事实，后来的状态相同也不能证明修改来源。
