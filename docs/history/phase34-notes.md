# 阶段 3/4：Hi-Res 与高采样率验证

2026-10-06 的受控实验完成 Hi-Res 开启、状态回读、96/192 kHz 协商与短静音播放，使用 `HeyMelody.Control`、`HeyMelody.Audio` 和 `HeyMelody.Experiments`。本页仅记录当时版本与设备样本，不证明当前发布包；现行工具和依赖见[CLI 说明](../cli-tools.md)与[仓库说明](../../REPOSITORY.md)。

| 层次 | 历史验证结果 |
| --- | --- |
| 耳机控制 | 唯一 Hi-Res SET `0403 [18,01]`，收到匹配序号、status0 的 ACK |
| 空间互斥 | 初始新空间模式为 0，无需实际关闭；活跃空间关闭路径经离线测试 |
| 重连与回读 | 断连后重新核验 X4、能力、Hi-Res=1 与空间=0 |
| 驱动能力 | 从 44.1/48 kHz 扩展到 44.1/48/96/192 kHz，无需 SYS 补丁 |
| 耳机 AVDTP | 96/192 kHz 配置、Start 均被接受，并关联到后续 LHDC5 媒体包 |
| 软件播放 | WASAPI engine/client 与 driver Streaming 分别确认 96/192 kHz；编码位深为 24 |
| 最终回读 | Hi-Res 开启，驱动目标为 192 kHz / 24 bit |

线上配置证据与应用下拉选项、驱动目标分别记录。测试发送短静音 PCM16，Windows 引擎为浮点32；这些证据不等于 DAC 时钟测量、逐样本 bit-perfect、始终无损或听感评价，未测实际码率、延迟、耗电及无损比例。

控制流程先确认精确 Product ID、配置摘要和能力；新空间模式优先，旧 feature `1B` 仅在新模式不支持时使用。空间状态或前置关闭未确认便停止。已可能发送的 SET 不自动重放，空 ACK 保留为未知，仅允许后续只读回查。

驱动及 WASAPI 端点按稳定设备身份关联，不能用名称或默认输出代替。采样率请求使用 `persist=false`，只针对 96/192 kHz；短静音播放不调整音量、不暂停其他应用、不强占独占端点。没有修改驱动 SYS、许可证、签名、驱动绑定或其他驱动选项。

96 kHz 的最终证据来自连续捕获，保留此前解析异常；关键 Reconfigure、Start 及媒体链位于异常之后，结论不声称整份捕获无错误。分析修正了 IRP 指针复用导致的去重问题，并把 DelayReport 作为元数据事务。原始捕获可能包含其他连接信息，完整日志与私有标识仅保存在本地档案，不作为公开文档附件。

Control 19 个离线场景、Audio 88 个离线断言、AVDTP 分析器 23 个离线场景通过，Release 及 ARM64 交叉构建均零警告、零错误。实机覆盖 96/192 kHz 的短静音播放、Streaming 回读和独立协议证据；没有 ARM64 实机播放、长时稳定性或声学输出测量。
