# 项目上下文读取风险排查（2026-10-11）

**存在明确的超大文本与超长单行读取风险，但尚不能确认它们造成了此前的 503。** 最大已测文本为 7,684,319 字符，最长单行为 1,678,970 字符。风险主要集中在研究数据、生成 HTML、资源 JSON 和运行快照；Markdown 最大约 6.2 万字符，普通项目源码最大约 4.9 万字符。后半程剩余上下文不足时，较小文档和多文件累计输出也可能超出预算。

## 503 与上下文：目前能确认什么

用户观察到：长会话后半程多次突然 503，会话中已有多次成功 compact，新会话可恢复工作。本轮未取得这些失败请求的错误正文、请求标识、实际输入 token 数和紧邻失败的工具结果，因此不能把“存在大文件”与“实际由大文件触发”视为同一结论。

OpenAI 的 API 文档将带 `service_unavailable_error` / `server_is_overloaded` 的 503 描述为模型暂时过载；Agents API 将 `context_length_exceeded` 单独列为输入超过上下文窗口。它们是诊断参考，不能直接证明当前 Codex 客户端的错误映射。需核对实际错误码及请求内容。[API 错误说明](https://developers.openai.com/api/docs/guides/error-codes)、[Agents API 错误说明](https://developers.openai.com/api/docs/guides/agents-api/errors)。

官方说明 standalone compaction 的输入仍须处于模型窗口内。此前成功 compact 不能证明后续新增工具输出一定能容纳；这是读取防护的理由，并不是这次 503 的因果证明。[Compaction 文档](https://developers.openai.com/api/docs/guides/compaction)。

文件在本地被流式扫描或解析，并不会自动成为模型输入；真正消耗上下文的是回传的正文、工具结果和代理消息。工具输出截断可能降低风险，但本轮未核实失败会话是否发生截断、如何计入请求。本文不假设当前模型窗口大小，也不把字符数当作 token 数。

## 后续代理直接执行的读取规则

以下是本项目保守的操作阈值，**不是模型规格，也不是保证不会超限的数学边界**。会话后半程应进一步缩小预算。不要单凭字节、扩展名或行数决定全文读取。

| 条件 | 读取方式 |
| --- | --- |
| 字符 >50,000，或最长行 >8,000 | **先主动调用 subagent 做限量结构预览**；subagent 同样禁止无限整读 |
| 未达到上一项，且字符 >12,000 或最长行 >2,000 | 先标题/符号/键名，按目标段读取，每段正文 ≤6,000 字符 |
| 字符 ≤12,000 且最长行 ≤2,000 | 确有任务需要时可整读，同时守住本次调用总预算 |
| JSON、HTML 数据块、data URI、密集快照 | 优先本地解析和字段投影，即使总字符较小也避免无用载荷 |

实际流程：

1. 先列路径和字节尺寸，再在本地流式得到字符、行数、最长行。已有快照只用于发现风险；文件有修改或版本不同，重新测量。统计工具不得把正文同时打印。
2. 明确要回答的一个问题和目标文件/版本。搜索先用 `rg -l` 返回路径或 `rg -c` 返回计数；大范围结果也限制总数量。不先对整棵 `research/` 做带正文的递归搜索。
3. 超长对象给 subagent 一个具体问题、文件指标、指定范围和返回上限；优先少量历史上下文的分支，回传 ≤4,000 字符的结构摘要、证据位置和下一步查询。父代理不再重复整读原件。
4. 单次工具调用回传正文合计 ≤12,000 字符，单段 ≤6,000 字符；并行调用的结果和多个 subagent 的摘要也合计计算。默认配合 `max_output_tokens` 2,000–4,000，先在生产输出的一侧截断字符；工具端 token 截断是另一层保护。
5. 按行读取必须同时限制每行和总字符。若结果已被截断，不把它视为完整内容，也不通过扩大预算重新倾倒全文件；改为更窄的查询。
6. 记录已查文件、摘要、章节/字段、结论与未闭合问题。compact 后按这些记录续查，避免把同一大对象和重复快照反复读入。

普通短行文档的定向检索示例（关键词与目标应按任务替换）：

```powershell
Get-Item -LiteralPath 'REPOSITORY.md' | Select-Object Name, Length
rg -n -F -m 12 --max-columns 240 --max-columns-preview '0.8.13' -- REPOSITORY.md
```

上述尺寸只代表字节，不能替代字符统计；列限制只用于预览，长行会被截断，不证明未显示部分没有命中。要看某条长行里的具体记录，应本地解析并投影。若已完成字符测量，只需限定字符预览，可用如下方式，避免“前 N 行”误读百万字符行：

```powershell
$auditReader = [IO.File]::OpenText('REPOSITORY.md')
try {
    $auditBuffer = [char[]]::new(6000)
    $auditCount = $auditReader.ReadBlock($auditBuffer, 0, $auditBuffer.Length)
    [string]::new($auditBuffer, 0, $auditCount)
} finally {
    $auditReader.Dispose()
}
```

这只是前 6,000 字符预览，不是完整阅读或编码通用工具。正式后续工具应提供元数据、指定行/字符范围、每行截断、总量截断、JSON 字段投影和明确的截断标志。

1. **优先读取防护。** 将短规则与本报告入口加入 `AGENTS.md` / 文档入口；提供按单文件计数和限量查询的维护工具，覆盖长行、跨文件及并行结果的总预算。新增工具在 `tools/research/`，研究时版本和验证产物保留在 `research/`。验收用上述百万字符 HTML、单行 Lottie 和 13 行日志，确认不会输出完整数据块，截断状态可见，目标字段可定位。

3. **增加研究查询索引。** JSONL/TSV、HTML 图册、完整会话转录分别按入口、资源键、主题和行范围建立索引。检索按 SHA256 去重展示，完整证据和快照不删。工具的大结果默认落到新的研究文件，终端只返回摘要。
