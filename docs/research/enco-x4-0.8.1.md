# Enco X4 控制连接回归与 0.8.1 验证

> 当前客户端仅使用欢律配置与资源，见[当前单源规则](heymelody-only.md)。下文涉及已退出支持来源的覆盖、接口和操作要求仅用于历史研究复核，已由当前规则取代；原版本、路径、摘要和验证范围保留。

本文为公开整理稿；[整理前完整原文](../../research/migrations/organization-2026-10-09/originals/docs/research/enco-x4-0.8.1.md)保存在本地研究档案，不随普通Git clone提供。历史版本、来源及验证范围保留，完整研究对象与产物由 `research/` 保存。

2026-10-08，本机 Windows 已连接 Enco X4、音频正常，0.8.0 却提示“蓝牙后台暂不可用”。只读探针成功发现 RFCOMM 通道 15，并完成型号验证和八项 GET；因此进一步检查应用的控制初始化。

## 原因与修复

两套资源目录均包含 X4 产品 ID `06EC10`，其控制服务为 `0000079A-D102-11E1-9B23-00025B00A5A5`。目录中其他型号还使用 `00001107-D102-11E1-9B23-00025B00A5A5`。资源驱动的连接器会枚举这两种服务，但旧的原生输入校验只允许第一种。即使已发现 X4 的 079A 服务，随后查询 1107 仍会抛出异常，尚未进入 RFCOMM 连接即失败。发布包中的校验也复现了此异常。

0.8.1 明确允许这两个完整 UUID，继续拒绝任意其他 UUID，并保留地址、通道范围、SDP 结果匹配和服务唯一性校验。离线测试从两套实际预装目录读取全部可用控制配置，检查它们与原生校验兼容，且不进行蓝牙调用。该测试已加入默认发布检查。

主界面现在仅在后台明确给出 `MonitoringState.Unsupported` 时显示“型号尚未适配”。尚未取得产品 ID 的等待、连接、暂停和失败状态分别显示控制连接状态；Windows 音频正常但控制初始化失败不再误报型号不支持。

## 本机实测

使用 `tools/Verify-ConnectedHeadset.ps1` 运行 0.8.1 x64 的真实私有 Host worker，每次只提交初始化、诊断和退出 RPC，不提交设置、不启动校准、不修改配对、名单、资源设置或缓存。四份成功报告记录 Host EXE、Host DLL、Windows DLL 和 Resources DLL 的文件摘要。当前脚本已扩展为记录 Host EXE、运行配置及全部 HeyMelody 依赖程序集摘要；扩展后的发布版独立 worker 报告因连接竞争未完成初始化，不作为成功实测记录。报告不包含蓝牙地址、会话标识、序列号或密钥。

| 资源来源 | 内容版本 | 配置选择 | 结果 |
| --- | ---: | --- | --- |
| 欢律 | 117006004 | 仅预装 | 通过 |
| 欢律 | 117006007 | 已缓存在线版本 | 通过 |
| 无线耳机 | 17006002 | 仅预装 | 通过 |
| 无线耳机 | 17006007 | 已缓存在线版本 | 通过 |

四种场景均读到产品 ID `06EC10`、固件 `116`、左右耳电量 `100%`、10 项功能状态和 3 个自定义 EQ。充电盒电量未上报，保持未知。控制连接就绪，查询警告为 0；每次提交 15 次 GET、0 次 SET、2 次通知能力／订阅请求，在随后五秒观察窗口内收到状态快照更新。

生成的本地执行报告位于 `artifacts/x4-fix-081`，原始失败报告保留，后续成功报告使用新文件名。发布后对比确认 x64 后台的全部九个 HeyMelody 程序集与上述实测构建字节一致。用户已打开发布版时，独立 worker 的连接会竞争；此时通过共享 IPC 的 observer 订阅读取现有状态，确认实际运行的发布版处于 `Monitoring`、控制就绪，读到上述型号、固件、电量和 10 段 EQ，未额外请求 GET 或 SET。独立验证脚本现在会在发现已有后台时停止，不干扰现有连接。

这些记录证明本机 X4 的对应 x64 worker 初始化和被动监听，以及运行中的发布版后台状态，不证明校准执行、设置写入、所有型号、整套 GUI 或 ARM64 硬件行为。

复验已发布的 x64 后台：

```powershell
pwsh -NoProfile -File tools/Verify-ConnectedHeadset.ps1 -HostPath release/HeyMelody_Windows_0.8.1/x64/backend/HeyMelody.Host.exe -Source HeyMelody -Bundled -OutputPath artifacts/x4-081-new-report.json
```

复验前退出项目的其他后台，避免同一耳机的 RFCOMM 连接竞争。脚本只终止自身创建的子进程，输出路径必须不存在。
