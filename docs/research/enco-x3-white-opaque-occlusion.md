# Enco X3 白色遮挡修复与黑色回归

2026-10-13，在 0.9.2 源码中修复 Enco X3 白色模型外壳显示内部结构的问题。方案沿用 [历史 X3 修复](enco-x3-opaque-occlusion.md) 与 [Free4 修复](enco-free4-0.7.1.md)：保留云端模型原件，在导入后的已知材质上关闭 Alpha 混合并开启深度写入。黑色模型已有对应规则，本轮补充回归，不能将白色问题描述为两种配色都缺少修复。

完整对象、来源查询、材质审计、验证过程及产物保存在本地 [research/enco-x3-opaque-20261013/](../../research/enco-x3-opaque-20261013/)，通常不随普通 Git clone 提供。此公开文档保留结论与复测入口；旧实验文稿及历史证据未改写。

## 资产与根因

本轮对 `productId=067410`、`moduleId=14` 的 `color=2`、`color=3` 分别核对欢律与“无线耳机”来源；在同一配色参数下，两来源返回相同 ZIP。两种配色的 ZIP 与 GLB 各不相同，不能据此混合来源参数或缓存。下表的黑／白名称依据基础色贴图采样与外观区分，未取得官方色号文案，不将请求色值当作通用颜色约定。

| 资产外观 | 请求配色值 | 原始 GLB SHA256 | 修复前行为 |
| --- | --- | --- | --- |
| 黑色 | `2` | `6f6ab09e3b5067d3f1d4fac732243bb5fe723e3eb982d9b84e629560e5813363` | 已命中现有不透明材质规则 |
| 白色 | `3` | `b2d5d94fabee06718eaf7378fe6bdbf3db2824db23656a080251df92a04a5060` | 未命中现有精确摘要规则，仍按 BLEND 导入 |

两份 GLB 均含 31 个 mesh、98,367 个三角形，使用唯一材质 `1001`。原件均声明 `alphaMode: BLEND`，但基础色贴图是无 `tRNS` 的 RGB PNG，基础色 factor 为默认 `(1,1,1,1)`，没有 `COLOR_0` 顶点颜色或透射材质扩展。这些证据支持本轮两份资产应按不透明外壳渲染，不能推广到未经审计的其他模型。

固定依赖 Ava3DControl 12.1.0-preview.16 将 BLEND 导入为 Alpha 混合材质且关闭深度写入。外壳绘制后，内部零件可能继续覆盖它，产生半透明或穿透外观。白色模型没有命中旧 X3 黑色摘要，因而没有执行已有修正；不是原始 GLB 被修改，也不是旧黑色规则丢失。

## 实现范围

导入路径通过内部 `ModelMaterialCorrections` 集中应用已有 Free4、Free4 丹拿版、X3 黑色规则，并增加上述白色 GLB 摘要。仅匹配已知 SHA256 时，把 `1001` 的 `Blend` 设为 `BlendMode.Opaque`、`DepthWrite` 设为 `true`；继续保留深度测试、剔除、基础色、全部纹理与几何。未知摘要的资产保持 SDK 导入行为。

材质修正在各视图的独立场景导入后执行，软件材质副本继续从修正后的材质生成。模型与贴图文件保持原字节；白／黑研究模型不加入应用包，普通 CI 与构建不依赖本地 `research/` 或网络。本轮不调整版本号，不操作真实耳机。

## 验证与复现

本轮 Release 应用与 ModelPreview 测试项目构建均为零警告、零错误。App 离线检查通过 113 项，覆盖四个已知模型摘要、未知摘要、非目标材质，以及 GPU／CPU 材质往返时不透明混合与深度写入的保持；不调用真实蓝牙。

白色的 [最终原生收据](../../artifacts/x3-opaque-20261013/white-final/report.json) 与黑色的 [最终原生收据](../../artifacts/x3-opaque-20261013/black-final/report.json) 各通过 82 项，实际后端均为 OpenGL、设备为 NVIDIA GeForce RTX 2060，各保留 31 次绘制和 98,367 个三角形。四个固定方向的像素对比如下；变化像素按 RGB 绝对差之和大于 12 计算，两款修正后逆序差异均低于原有 0.3% 容差。

| 方向 | 白色原始 BLEND 与修正后变化像素 | 黑色原始 BLEND 与修正后变化像素 | 两款各自修正后逆序变化像素 |
| --- | ---: | ---: | ---: |
| 正面 | 12,377 | 12,910 | 0 |
| 斜角 | 15,440 | 16,551 | 0 |
| 侧面 | 16,729 | 17,739 | 8 |
| 背面 | 33,868 | 34,425 | 0 |

已目检白色正面原始图与 `white-final` 最终修正 SDK 帧：外壳恢复遮挡，原有可见内托仍保留；黑色最终正面修正 SDK 帧外壳也正常。

黑色的前两次运行仅因附加 Win32 `BitBlt` 桌面截图失败退出，没有模型断言失败；失败收据与日志保存在完整本地档案。外部模型入口现将这类附加桌面截图失败记录为 warning，黑色最终收据记录两条此类 warning；必需的 SDK GPU 渲染捕获和遮挡阈值仍严格检查，原有 Free4 入口的桌面截图检查也保持严格。旧 Free4 严格入口因同类 `BitBlt` 错误停止，错误前 23 项检查没有失败，不能视为完整通过。

另以未改写的原版 Free4 GLB 运行 [外部基线验收](../../artifacts/x3-opaque-20261013/free4-external-final/report.json)，通过 82 项，实际 OpenGL／RTX 2060 后端保留 28 次绘制、67 个 node 和 93,875 个三角形。四方向原始与修正画面分别变化 13,690／4,161／17,514／4,750 像素，修正后逆序差异为 10／6／5／0 像素，最大比例约 0.00286%，低于 0.3% 容差。最终正面修正 SDK 帧已目检，外壳遮挡正常；收据保留两条附加 `BitBlt` warning，并确认必需 SDK 帧已捕获。此结果验证 Free4 的共同材质修正路径，未补齐旧严格入口失败的桌面截图。

三份最终收据对应相同的 App 程序集 SHA256 `7b56d3e83d7c8a40259dee56b56e8af343e051e0a94ac3c15d14ad1ec7f0367c`，Ava3D 程序集为 `f4f88fefb1f634d16fe441aba26a93a5bee1bfcc2e54f90bd033fec13e16a50c`。

在 Windows 上使用 .NET 10 SDK，对本地保存的任一原始 GLB 执行：

```powershell
dotnet run --project tests/HeyMelody.ModelPreview.Tests -- --native-occlusion --model-file <path> --output-dir <new artifacts path>
```

白色与黑色分别使用独立的新输出目录。外部模型入口复用原生遮挡验收：在相同光照和固定相机下对比原始导入与应用修正后的画面，再反转 sibling 插入顺序，检查修正后的可见外壳是否稳定；保存渲染图与包含模型摘要、材质、几何及实际后端的收据。此命令使用本地 GLB，不下载资源、不调用蓝牙、不改写原件。

上述结果证明本轮源码程序集在 Windows x64 模型测试窗口中的行为，没有完整启动用户客户端或操作真实耳机。其它 GPU、ARM64 硬件和手机端材质一致性未验证；软件渲染仍受 [已有材质与光照近似](software-model-materials.md) 限制，离线 GPU／CPU 材质往返检查不等于 X3 软件后端画面验收。
