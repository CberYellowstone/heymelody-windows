# 研究资料规范与整理记录

**`research/` 存放完整的研究对象、完整理解、研究结论和研究产物等；经过整理、适宜公布的研究结果整理到 `docs/`。** 此规则同样适用于新增研究和已有资料，根目录 [AGENTS.md](../../AGENTS.md) 为后续工作保留此约定。

## 完整研究档案

按主题在 `research/<专题>/` 保存对象原件及来源、版本和摘要，以及对对象的完整解读。解读应包含分析过程、符号或调用关系、依据、已确认结论、失败尝试和未闭合问题；不能只留下成功结论或公开摘要。脚本、反编译、配置、模型、图片、日志、抓包和验证收据等产物与其来源一起保留。

各专题 README 说明对象、完整报告、产物、复现入口和验证范围。补充研究另存记录，不覆盖原稿；历史日期、版本、采样路径和摘要保留原值。整理或迁移前先归档原文，再核对文件大小与 SHA256，当前访问位置另写映射。

## 公开文档与项目工具

`docs/` 保存供读者使用的整理稿：明确研究问题、主要依据、结论、实现影响、适用范围和仍未验证的内容。可以保留必要的协议、型号、来源摘要及技术细节；逐项原始勘证、完整机器快照、本机环境、操作流水和个人设备数据留在研究档案。公开整理不会修改完整原件。

文档应区分静态分析、模拟测试、原生窗口检查和真实设备验证，标出历史版本。完整本地档案链接可作为继续研究的入口，但应明确这些原件不随普通 Git clone 提供；缺少本地档案不影响理解公开结论或正常构建。

供项目持续使用的复现、提取和验收工具放在 `tools/research/`，对应原始版本及运行产物仍保留在 `research/`。专题工具默认将新的研究输出写到 `research/`。应用资源、必要测试 fixture、第三方许可、普通构建验证与发布包继续使用 `src/`、`tests/`、`docs/licenses/`、`artifacts/` 和 `release/` 的现有规则。

`research/` 沿用现有忽略规则；已跟踪的七份小型静态契约保留原位置和跟踪状态。本规范不改变原件的许可或提交范围，也不要求把完整研究输入加入 Git。
