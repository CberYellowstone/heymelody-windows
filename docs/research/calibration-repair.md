## 当前行为

2026-10-14 固件策略适用于贴合度和黄金听感：来源最低固件条件不符或无法判定时，仅在主界面右上角显示 warning，不单凭固件版本禁用向导。App 条件、已实现的测试协议、设备实际能力、佩戴/通话/忙碌状态、当前连接及校准独占权仍按原规则检查。提示不证明该固件已通过实机测听；原始条件与以下历史验证边界保留。

贴合度检测使用`0109`确认双耳佩戴，再提交`0405 [01]`。收到event4的左右结果后提交`0405 [00]`并等待确认，才显示完成。`0107`是OTA能力，已从佩戴查询中移除。开始ACK不算检测结果，电量、通话、TWS、佩戴及忙碌状态分别提示；不虚构20%电量门槛。

黄金听感由资源中的`earScan`选择流程：支持耳扫则先扫描后进入滑块测听，否则进入旧版“听到/没听到”流程。`hearingJudgeDb`仅控制左右选择差异提示。耳扫结果必须匹配本次UID且blob非空；先停止扫描、确认ACK并等待600ms，再允许继续。耳扫守卫20秒，覆盖固件自身约15秒测试。

每耳依次测试六个频段。X4 `06EC10`显示已核实的500/1000/2000/4000/6000/8000 Hz；其他产品仅显示频段编号。滑块每项从index5/`-19`开始，返回上项也重置该默认值。改变音量先提交单字节`040E [04]`暂停，再发`[03,01,side,type,db]`；界面在300ms后提交最后选择，鼠标或键盘释放立即提交。界面保留待确认选择，直到耳机ACK对应档位，才允许“继续”。指导语为找到声音刚好消失的位置。

event8的音乐、通话及佩戴中断暂停当前项，恢复条件明确后由用户继续，不自动记录答案；同时存在多个中断时必须全部解除。噪声提示独立于测听答案。活动或暂停测听连续120秒无操作会停止本次检测。结束12项后停止测听并请求完整滤波数据，加载失败保留答案并允许重新获取。

| 通道 | 当前解释与完成条件 |
| --- | --- |
| `0116/8116` | 10字节头：status、signed BE32 UID、deviceType、LE16 totalSamples、packetId、enhanceType、float32LE数组 |
| `011F/811F` | 11字节头：status、UID、deviceType、LE16采样率、LE16 totalSamples、packetId、float32LE数组 |
| 聚合 | 按左右样本数完成，保留独立来源及元数据；匹配UID，拒绝非有限值、冲突重复及超量数据 |
| SDK边界 | 普通格式每耳total/2；total384每耳384。device4每片严格包含total个float，384需两片各192/192；不猜不足长度的双耳分片布局。packetId按Java signed Byte顺序合并 |

X4实测`8116`是250字节、60个系数，`811F`是299字节、72个系数；250/299是包长，不能当成样本总数。对应回归fixture保留真实头部布局及长度，使用合成UID和系数。带耳扫设备必须收齐两类左右数据，才开放结果、试听及保存。

结果页提供原音、黄金听感和结束试听。试听切换`040E action1`及可选`0415 action1`的临时DSP参数，由用户播放熟悉的音乐；测听纯音由耳机内部生成。结束试听用`040E [02]`及可选`0415 [02]`，取消/关闭清理本次持有的检测与试听。停止未确认会报告失败并保留校准独占权，允许重试停止；确认前不把窗口关闭或Host退出回执写成成功。

保存前检查名称、完整12项、扫描数据、现有方案替换许可和本机历史容量。新名称原样提交，限制为1..39个UTF-8字节。保存链为`0411描述 → 040E action3 → 可选0415 action3 → 0403[0B,01]`，然后分别GET`0115/011E/0118/010D`核对阈值、UID、名字、扫描blob、描述编号和启用状态。全部确认后才写本机历史并显示完成。旧JSON历史缺失的新字段可补足；较长旧显示名可使用独立wire名应用，未伪造扫描数据。UID0旧历史仍可读取，但X4固件不提供其有效方案读回，因此应用前拒绝该记录，不发送设备指令。

## 连接与界面集成

仍由共享Host持有唯一蓝牙reader，通过带handle、generation和revision的IPC驱动两个独立向导。新增状态传递待选档位、音量ACK、滤波完成、试听模式、恢复条件、噪声及左右差异提示。

`0200`宣告的事件与`8205`逐项注册成功分别记录，批次status0不代表每项成功。X4可能拒绝主动订阅event4/8且未宣告event14，但仍发送被动校准结果，故不据此禁用功能。`8116`和`811F`首包及后续包均送达引擎，匹配请求的首包同时作为GET响应；一致重复不重复累计。每轮滤波请求只聚合对应响应序号；首回执前的分片有界缓存，旧轮次成功或失败包不影响重试，新`0116`同时废止旧`011F`关联。

已提交指令使用独立、有限的回执等待；取消界面输入不会取消共享reader，先接收该回执再停止。测试期间不因序号剩余少于32而自动重建连接。每个连接仍不重复序号，最后8个保留给暂停/停止；保存起点至少剩16个序号，保证保存及读回后仍留清理余量。达到边界明确结束并提示重连，结束后普通刷新可以安全建立新连接。这不保证无线链路本身不会断开。
