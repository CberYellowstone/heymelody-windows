# 降噪区域的通透人声与模式名称核查

> 当前客户端仅使用欢律配置与资源，见[当前单源规则](heymelody-only.md)。下文涉及已退出支持来源的覆盖、接口和操作要求仅用于历史研究复核，已由当前规则取代；原版本、路径、摘要和验证范围保留。

2026-10-11 对降噪 Expander 中的模式配置作小范围审计。依据是欢律 17.6.5 的本地 APK 资源与反编译代码、两来源设备配置及当前 Windows 实现；本轮没有重新操作真实耳机。完整输入摘要、原稿保全、原 App 控件证据和未闭合分支见本地[研究档案](../../research/anc-transparency-20261011/README.md)。

## 通透下的强化人声

Enco X2、Enco X3 的通透父模式为 `modeType=2`，其两个子模式分别表示普通通透与强化人声。欢律的正式标题是 **“强化人声”**，说明是 **“弱化环境声的同时突出人声”**；本地资源未找到“人声凸显”字面量。该功能不等于音乐音效设置中的“人声增强”。

原 App 在设备详情的噪声控制主模式下方显示 `MelodySwitchPreference` 设置行。Windows 对应使用设置行与 Avalonia `ToggleSwitch`，只在选择通透并有可识别的两个子模式时显示；开启、关闭分别提交配置中的对应子模式协议值，不再把它显示成“降噪／降噪档位9”的 ComboBox。“未确认”表示子状态尚未读取，不将未知值当作关闭；状态回填不提交设置，连接和能力允许时仍可明确点击。

## 独立聆听与其他模式

同一个 `modeType=6` 在不同层级具有不同意义：通透下的子模式是“强化人声”；独立主模式是 **“聆听”**，说明为 **“减弱周围噪音基础上保留人声/广播声”**。Enco Free2、Enco Free2i、Enco Air2 Pro 和 Enco R Pro 的配置属于后者，应保留为主模式选择，不生成通透子开关。协议值与显示名称分开处理，不能把这些型号的协议值 3 命名为“降噪档位3”。

| 配置上下文 | 名称与处理 |
| --- | --- |
| 主模式 `10` | 自适应；原文说明为“实时融合主动降噪与通透模式，根据所处环境噪声的变化，控制耳机中的噪声水平” |
| 主模式 `7` | 智能降噪；与降噪效果子选项 `7` 的“智能切换”区分 |
| 主模式 `3 / 4` | 弱降噪／强降噪；对应效果子选项为轻度降噪／深度降噪 |
| 效果子选项 `8` | 中度降噪 |
| 主模式 `5`，无细分选项 | 降噪；不生成“降噪档位0”名称 |
| 自适应子选项 `11 / 12 / 13` | 更少噪音／标准／更多噪音，保留现有 ComboBox |

原 App 的自适应子选项入口是“自适应降噪范围”设置行，打开底部单选弹窗，正文为“根据环境噪声变化，动态调整降噪与通透的权重”。本轮只确认其语义和原控件，保留 Windows 现有三选项控件。智能降噪主模式的专属详情说明绑定尚未闭合，不能套用自适应的降噪与通透融合说明。

## 能力与验证边界

两套来源按整份配置选择；显示名称和控件不增加控制权限。功能仍须满足当前来源配置、已实现 codec、固件和设备能力条件。连接、来源或设备发生变化后重新读取；未知回执、失败或超时不重放设置。选择父模式只提交父模式，不为恢复开关额外发送子模式 SET。

本轮默认 13 个验收程序全部通过；相关 JSON 报告为校准界面 13 项、Host 88 项、Client 163 项、App 112 项，均为 `success`、`nativeBluetoothCalls=0`。额外的降噪局部 UI 6 项在布局修正后再次通过。仅打开过一次小型局部拼图：首版把开关放在设置行 Footer，导致错行和裁剪；修正为内容 Grid 并补充真实坐标断言后，修正截图未打开。完整命令、日志摘要和初版失败保全见研究档案。本次降噪改动未进行原生窗口或真实设备验证，不进行完整 UI 截图审计；Client 报告的 X64 架构也不能证明 ARM64 硬件效果。
