# 界面审计与渲染性能（0.9.0）

**0.9.0 重排了主窗口、设备管理器和两个校准窗口中不合理的布局与交互，去掉三维模型的 30／60 帧上限，并把界面线程与渲染线程上的逐帧开销降到可以跟随 120 Hz 显示器的水平；界面固定使用简体中文字体。** 所有结论来自源码审计、上游源码核对和 Linux 无头测试；**本轮没有在 Windows 显示器上实测帧率**，验收方法见文末。

## 依据与方法

审计覆盖 `HeyMelody.App`（主窗口、控制面板、设备栏、设置对话框、三维与动画视图）、`HeyMelody.DeviceManager`、`HeyMelody.Calibration.UI`（贴合度与黄金听感）和 Host 托盘，并核对 Avalonia 12.1.4、FluentAvaloniaUI 3.1.0、Ava3DControl 12.1.0-preview.16 的源码或程序集。与 120 Hz 相关的上游事实：

- Win32 的 WinUIComposition（提交完成驱动）与 DirectComposition（`WaitForCommitCompletion`）都按显示器刷新率出帧；`TopLevel.RequestAnimationFrame` 每个已合成帧回调一次。Win32 `DispatcherTimer` 基于 `SetTimer`，粒度约 15.6 ms。
- FluentAvalonia 3.1 的设置卡展开／收起动画是界面线程上的关键帧动画（`TranslateTransform.Y`，展开 333 ms、收起 167 ms），每帧都需要界面线程空闲。
- Ava3D 的 `MaxFrameRate` 为绝对上限（0 表示不限），在宿主渲染线程绘制；CPU 后端在 16 核桌面机上对 12.8 万三角形场景约 55 fps。

120 Hz 下每帧约 8.3 ms：界面线程每帧只应做动画采样，不触发布局、不重建控件、不遇到首次 JIT；渲染线程上三维、Lottie 与 WebP 合计应低于这一预算；且不能有固定帧率上限。

## 简体中文字体

Avalonia 的回退匹配把文本区域性（为空时取界面区域性）作为 BCP-47 标签交给 Skia／DirectWrite 打分，英文 Windows 上汉字可能落到日文字体。0.9.0 把界面区域性设为 zh-CN，默认字体为系统 Microsoft YaHei UI，汉字回退在打分前固定到同一字体，550–699 字重映射到真实粗体字面；显式设置完整 hinting 与像素对齐基线，抗锯齿由 Avalonia 在不透明表面用子像素、在图层与 Mica 区域用灰度。没有雅黑时使用随附 Noto Sans SC（OFL-1.1，未修改）。

实施中发现：在 Avalonia 12.1.3 与 12.1.4 中，用 `EmbeddedFontCollection` 从流加载的大型中文字体会让每个绘制该字体的窗口约多保留 10 MB 原生内存，同一字体作为系统字体打开则不增长。因此 Windows 有雅黑时完全不加载随附字体；Linux 无头预览与测试通过 fontconfig 以路径打开随附字体；只有在没有雅黑的 Windows 上才回落到流式集合，并在源码中注明代价。托盘提示与任务栏标题由 Windows 绘制，不受这些设置影响。

## 验证范围

Linux x64 无头环境（2026-10-11）：App 92 项（含 3 项排版、3 项帧循环）、设备管理器 8 例、校准界面 13 项、Client 158 项、Calibration 55 项、Protocol 65 项、Resources 25 项、Devices 19 项、Control 19 项、Daily 131 项通过；ModelPreview 运动检查 180 项通过（含 120／165／240 Hz 与不均匀帧间隔）；`win-x64` ReadyToRun 交叉发布可生成预编译程序集。改动前在同一环境的基线为 App 86 项，其余检查数与上述相同。Windows 打包由 CI 完成。

未验证：Windows 显示器上的实际帧率与帧时间、原生窗口检查（`--native*`）、Windows 离线检查、真实耳机、ARM64 执行，以及 en-US Windows 上的目视字形。在 120 Hz 显示器上验收时：设置 `HEYMELODY_RENDER_DIAGNOSTICS=1` 或按 Ctrl+Shift+F12，展开／折叠设置卡、拖动并放开三维模型、播放黄金听感试听，观察叠加层的帧率与帧时间曲线及模型左上角的 Ava3D 统计；空闲窗口不出帧，数字没有意义。
