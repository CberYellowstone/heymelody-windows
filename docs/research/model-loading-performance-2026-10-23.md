# 模型加载性能记录（2026-10-23）

本文记录 [UI-11 交接书](model-loading-handoff-2026-10-23.md)的 Windows x64 实测。当前已填入优化前基线、托管、SHA 阶段与 drain 配对门槛。drain 移除候选未达到保留门槛，最终保留原屏障；完整优化收益仍待最终配对对照。

## 测量方法与构建身份

- 基线起点为 `f17ab2b5b58e6c9bdbbc93f7ac3bb74c840582dc`，另加纯计时、独立 benchmark 及专用验收入口，保留原有串行读取、探测、原生 SHA 和 drain 行为。
- 运行真实 `HeyMelody.exe --model-loading-benchmark`，使用产品 `DeviceModelView`、Avalonia、Filament 原生运行库和真实 Win32 窗口。此入口只显示独立模型区域，没有走设备选择或美术 RPC，也没有请求蓝牙操作。
- Vulkan、OpenGL 各测三个资源来源。每个后端/来源启动 5 个新进程，每进程先冷加载一次，再移除模型、显示非模型美术并重附加 5 次，共 30 个进程、180 个加载样本。每组冷样本为 5 个，热样本为 25 个；热样本在同一进程内有关联。
- 冷加载指本进程第一次附加模型至首张尺寸匹配的帧呈现；没有清除操作系统文件缓存或驱动缓存。热加载保持同一后端，经过实际脱离与重附加，不以切换后端代替切换设备场景。
- 使用单调时钟，首帧结算一次。各阶段可能重叠，总耗时独立测量，不能把分段中位数相加作为总计。读取阶段在共享任务完成时取时间戳，后续阶段仍以同一边界比较。
- 独立模型区直接构造模型视图，覆盖读取、缓存与渲染器创建；没有调用 `DeviceVisualCatalog.Complete`，因此没有测量美术解析后提前预读/探测在真实 RPC 路径中的提前量。

## drain 移除的配对门槛

## 验证边界与复核入口

- Windows 基线全量 App 验收先因 BUG-03 的 ANC 行几何断言失败，未因此宣称全量通过。使用保全的基线 App 程序集独立运行美术验收，同样在 BUG-04 的“每项设置均为图标卡片”断言失败；不是由本轮加载改动新引入的证据。
- 基线 benchmark 的 PNG 保存曾把实际 RGBA 字节声明为 BGRA，导致保存文件的红蓝通道互换。原件保全；后续保存改为 RGBA8 并在收据中标记。此问题不影响产品画面或已记录的首帧计时。颜色验收需使用统一正确编码的另行原生 capture，不能直接将这些旧 PNG 当作颜色基准。
- 本地 `Compare-ModelLoadingPng.py` 只读比较保全的模型 PNG，必须显式选择旧图的 R/B 交换规则，输出原 PNG 摘要、不同像素数、最大通道差及平均绝对误差。它按坐标比较编码后的 RGBA 数值，包含 alpha，不应用颜色管理或图像对齐；统计结果也不能替代模型区域的视觉检查。
- `native-recovery` 的恢复路径没有装载模型，不能作为原生 GLB 摘要拒绝的证明。实际 C API 的篡改拒绝与 drain 候选实验另行记录。
- ARM64 真机、真实耳机效果、完整设备选择/RPC 链路及本轮 CI 结果须分别记录，不能由本页 x64 模型区基线推断。
- 完整原始计时、构建清单、环境、日志和截图保存在本机档案；[本地基线证据索引](../../research/model-loading-2026-10-23/baseline-evidence-index.json)指向 D 盘附件。这些本地资料不随普通 Git clone 提供。失败或未完整的批次保留原件，并排除出上述统计。
