## 必须区分的处理规则

此次云端 `.headset` 文件是 UTF-8 JSON。APK 内认证材料、APK 内置名单与安装私有缓存各有不同的 AES-GCM 链路；不能将云文件扩展名解释成加密格式。内置名单及私有缓存还包含 gzip 封装；私有缓存密钥由每次安装本地随机生成，与网络认证材料不同。

API 请求版本来自 application meta-data，而非 manifest 安装版本：欢律为 `17006004`，无线耳机为 `17006002`。欢律内置加载器给元数据版本加一亿，形成内置有效内容版本 `117006004`；这一换算不应用到请求或云文件版本。文件版本用于判断是否重新下载，有效内容版本用于判断是否采纳配置。

兼容字段按非 null 规则优先采用，空列表和 0 仍是有效值。启动时选择有效内容版本更高的一整份配置，相等时内置优先；运行中只发布严格更新的内容。此次两个云样本都满足采纳条件，不能据此制定无条件云端覆盖规则。

配置声明只提供适配线索。Windows 可写能力还需结合精确产品 ID、已核实条件、设备命令回报、协议解析和状态确认。Android 系统服务或音频能力声明也不等于 Windows 已获得相应控制、LHDC 或无损音频链路。

服务端元数据没有配置 SHA256 或独立内容签名；本地摘要是证据指纹，不能称为厂商数字签名。原 HTTP 元数据传输字节未保留，无法重新计算其传输摘要。临时缓存测试 key 未保留，离线复核只能检查旧文件及记录，并用新 key 重做加解密，不能跨进程再次解密原测试密文。Android TLS pinning 和完整缓存生命周期仍不在已证明范围内。
