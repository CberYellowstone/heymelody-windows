# 通知分类与顶部状态提示（0.8.12）

## 问题与依据

现有注册逻辑将所有已请求事件的拒绝都计入日常状态告警。此前校准研究确认：0200 的声明能力、8205 的逐项注册成功和被动结果接收是不同事实；X4 可以拒绝事件 4/8 的主动订阅，仍提供被动校准结果。历史依据见[校准修复](calibration-repair.md)，其日期和实机验证范围不变。

## 实现与范围

日常事件为 1/2/3/5/6/15，校准事件为 4/8/14。完整有效的批量成功响应、以及现有兼容逐项响应中，校准明确拒绝不产生日常订阅告警。日常拒绝、能力查询失败、整体失败及缺失或异常响应仍提示。规则依据事件类别，适用于所有型号和资源来源，不假定所有型号均已实测。

注册请求、声明能力、真实成功集合、被动接收及控件权限不变。刷新保留仍有效的日常订阅故障，连接更换清除旧会话告警。没有修改公共 API 或 IPC。

耳机状态提示移到顶部连接状态右侧，用“·”分隔。无提示隐藏圆点；长提示单行省略并提供完整悬停文字，多条在行内用“；”连接。独立操作失败提示保留，固件版本仍仅在设备信息显示。降噪沿用 0.8.11 已完成的默认展开 Expander。

## 验证范围

本轮验证使用内存传输及模拟 UI，不操作真实耳机，不新增实机验证结论。用户报告此前游戏音效切换后出现两次重连提示音，仅记录，触发操作和原因未确定。

全部 13 个默认检查程序通过，其中 Daily 129 项、App 93 项；另行通过 59 项原生模拟窗口检查，蓝牙调用和设置提交均为 0。检查了明暗主题及宽／窄窗口截图。x64 自包含包静态检查通过，ZIP 的 2841 个文件路径、大小及 SHA256 与发布目录全部一致。

完整本地依据、修改前原件和验证记录存放在 [研究档案](../../research/notification-header-20261010/README.md)；原件不随普通 Git clone 提供。普通构建与包检查报告位于本地 `artifacts/release-0.8.12-x64/`，发布目录为 `release/HeyMelody_Windows_0.8.12`，检查包为 `release/HeyMelody_Windows_0.8.12_x64.zip`。检查前需关闭旧主窗口并从托盘退出旧后台。
