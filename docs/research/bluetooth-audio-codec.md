# 蓝牙音频编码：可行性审计与撤回结论

2026-10-11 复核中断会话留下的未提交实现，并分析用户提供的 Bluetooth Tweaker 1.4.9.1 安装包与参考截图。目标是在设备信息中同时显示“当前连接协商的编码”和“耳机支持的编码”，包括 LHDC；约束是完全不提权、不安装特权驱动或服务。

在本轮查证范围内，没有取得满足上述约束并达到参考工具同等能力的已验证方案。因此撤回本次 codec 功能及其依赖，**功能未纳入 0.9.2**，保留已提交的 Enco Air4 Pro SPP 发现与诊断修复。这是本项目基于已知方案和约束作出的取舍，不是 Windows 所有普通权限路径均不可能的证明。

## 参考工具的方法与权限边界

对安装包、程序和驱动的静态分析表明，参考工具通过 `BtTweakerFltr` 内核过滤驱动观察 AVDTP 能力与协商数据，使用自定义 ETW 通道传递观测，区分耳机支持列表与 Windows 选中的编码。刷新路径还包含主动查询，不能将整个机制描述为纯被动监听。

LHDC 名称由标准／厂商编码标识映射得到：例如厂商 `0x053A` 配合 `0x484C` 或 `0x4C35` 分别对应 LHDC 与 LHDC V5。识别这些标识不要求识别程序本身提供 LHDC 编码器；支持列表也不能单独证明当前连接选中了该编码。

界面程序声明 `asInvoker`，但安装包同时部署内核驱动与 LocalSystem 服务。界面正常启动时不弹 UAC，并不等于这套能力无需预先安装特权组件。官方 [Bluetooth Tweaker FAQ](https://www.bluetoothgoodies.com/tweaker/faq/) 也明确安装／卸载需要管理员权限。该机制不符合本项目本轮的权限约束。

## 遗留实现的复核结果

- Windows 采集层使用 Microsoft A2DP ETW 与 Savitech 私有 GET 两条路径。ETW 会话控制要求管理员、Performance Log Users 或系统服务身份，不能作为普通用户通用可用的前提，见 Microsoft [StartTraceW](https://learn.microsoft.com/en-us/windows/win32/api/evntrace/nf-evntrace-starttracew)。
- Savitech 分支即使读取成功也始终返回未知；字段含义与普通账户访问权限尚未闭合。旧记录中的 `Applies=false`、原生 GET 次数为零，不能证明读取成功。数据契约也未提供耳机支持编码列表。
- Client 的设备选择动作可能将仍有效的后台观测隐藏成未知；快照有效性判断与对象引用耦合，切走再切回后需要新的快照才能恢复显示。旧测试将这种行为写成预期，不能据其通过认定符合目标体验。
- 代码后来保留的是连接的协商编码，公开说明仍写成仅在播放时有效。暂停播放后保持有效协商值本身可以合理，问题在于语义与文档未同步，不能将其直接称为仍在播放的证据。

以上代码、测试、依赖和对应的功能说明已退出当前实现；旧文档及研究证据按原样保全，不改写成已经完成的功能记录。

## 证据与验证范围

本轮进行了安装包／二进制静态分析、工作区差异审计和撤回前的纯离线基线验收。Windows OfflineChecks 通过 codec 96 条、组合采集器 17 条、Savitech 31 条合成断言及既有 SDP／ABI 检查；这些结果不证明真实耳机编码、普通权限访问或 ARM64 硬件行为。本轮未安装参考工具、未提权，未通过播放或设备设置操作验证编码，也未开展完整截图 UI 审计。

撤回后使用 .NET 10.0.401 完成 Windows x64 离线验收：App 与 Host Release 构建均为零警告、零错误，Client 163 项、Host 84 项、App 106 项及 Windows OfflineChecks 全部通过，未调用真实蓝牙设备。App 默认验收生成的图片仅保存在本地，未打开或上传。帧循环检查保留适配软件空闲 30 fps 的 40 ms 测试间隔；应用渲染实现未改动。
