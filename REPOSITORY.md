# Source repository

GitHub: https://github.com/CberYellowstone/heymelody-windows (private).

This directory is an independent Git repository. Source, tests, build scripts, release-owned resource bundles and curated documentation are versioned. `research/` retains complete research objects, understanding, conclusions and products: APKs, installers, screenshots, upstream checkouts, decompilations, full reports, tools and evidence. Curated results suitable for publication belong in `docs/`; maintained reproduction tools belong in `tools/research/`, with their original research versions archived locally. Generated packages remain in `release`, ordinary application verification remains in `artifacts`, and build outputs and Python caches remain local. Original APKs and Surface screenshots are not redistributed. Source-qualified catalog and artwork bundles under `src/HeyMelody.Resources/Bundles` are built from pinned local inputs by `tools/bundle_resources.py`; ordinary builds and runtime do not require the archival inputs. The two supplied X4 PNGs and verified X3/Free4 models retain their own provenance and exact identity restrictions. Asset rights are described in `packaging/licenses/Extracted-Earphone-Resources-NOTICE.txt`.

The [research organization rule](docs/research/organization.md), also recorded in [AGENTS.md](AGENTS.md), distinguishes the full local archive from the public result. The [research index](docs/research/README.md) and [tool index](tools/research/README.md) record current locations; historical reports and manifests retain their sampling paths. Seven previously tracked research contracts remain tracked in place. Start further device work at the [device adaptation handoff](docs/research/device-adaptation-handoff.md). Its acceptance tool creates new reports under `research/cloud-acceptance` without overwriting historical evidence. Full local archives are not included in a normal clone.

Version 0.8.5 corrects the flat, over-bright software model appearance. Each mesh receives a cloned CPU material whose metallic, roughness and emissive factors represent the map regions covered by its UV triangles, weighted by world surface area; emissive samples are decoded using the pinned renderer's sRGB gamma approximation before averaging. Software lighting preserves curvature without clipping the lit vertex colors. GPU rendering restores the original material references and previous lighting, and Automatic applies the fallback when its actual renderer is software. Original GLB and base-color bytes, full geometry and rotation interaction are retained. This is a bounded approximation of maps the pinned CPU backend omits, not per-pixel normal or occlusion rendering. See the [software material audit](docs/research/software-model-materials.md) and [rendering settings](docs/model-rendering.md).

The Python harness creates a new report and refuses an existing output file. It does not check every managed DLL, embedded artwork or ZIP integrity, and does not run the package. Use the PowerShell verifier for combined three-architecture package checks. The pre-migration x64 preview's separate ZIP/GLB integrity and launch evidence is linked in the Free4 record. Neither static verifier establishes hardware execution or native ARM64 execution.

Optional schema-2 successful execution receipts must match this release version and the exact GUI, DeviceManager, FitTest, HearingSetup and Host executable hashes for each asserted architecture. `Build-Client.ps1 -ValidationPath` validates and copies receipts; it does not collect evidence. Static reports are not execution receipts, and ARM64 cross-publishing does not prove native Bluetooth execution.

When supplied, historical read-only Bluetooth evidence is checked for product `06EC10`, positive GET submissions and zero SET/other submissions. Receipt flags do not establish execution of new calibration or other models. `tools/build_validation_summary.py` summarizes nine historical stage 3/4 files; its unbound schema-1 output cannot validate the current package. `tools/phase5_reference_checks.py` performs historical APK/profile assertions, requires the original `reference/` inputs, and now writes a new report under `research/phase5-protocol-evidence/` without overwriting an existing file.
